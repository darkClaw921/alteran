# Как участвовать

Спасибо, что заглянули. Ниже — минимум, который нужно знать, чтобы правка прошла быстро.

## Настройка

```bash
pnpm install
pnpm typecheck && pnpm lint && pnpm test
```

Нужны Node ≥ 22.5, pnpm 10 и `ripgrep`. Для контейнерного набора — ещё docker.

## Перед тем как открыть pull request

```bash
pnpm lint && pnpm typecheck && pnpm test
```

Это ровно то, что делает `ci.yml` на Node 22 и 24, так что локальная зелень почти всегда означает зелёный CI. Если правка касается прав, хуков или планировщика, стоит дополнительно прогнать `pnpm test:sandbox` — но помните, что этот набор выполняет настоящие команды и рассчитан на одноразовый контейнер.

Правила, которые чаще всего ломают сборку:

- **Линтер обязателен.** `pnpm lint` не должен выдавать замечаний. Формат — `pnpm format`; дерево уже отформатировано под Biome, поэтому повторный прогон обычно ничего не меняет.
- **Не смешивайте форматирование с логикой.** Если `pnpm format` что-то переписал, держите это в том же коммите, что и код, к которому оно относится, а не отдельным «formatting-only» коммитом.
- **Тесты идут без сети.** Провайдеры подменяются скриптованным заглушком (`test/scripted.ts`), TUI работает на поддельных TTY (`test/harness.ts`). Тест, которому нужен реальный ключ или сеть, в этот набор не вписывается.
- **Никаких `git commit` / `git push` в коде агента.** Агент обязан спросить пользователя; это не стилистическое пожелание, а требование безопасности.

## Стиль

Код — ESM, TypeScript в strict-режиме, комментарии и сообщения — по-русски в UI и по-английски в коде, как сложилось в репозитории. Комментарий объясняет *почему*, а не *что*: `Runtime.budgetCheck` существует потому, что лимит должен остановить запрос до его оплаты, и это стоит написать.

Архитектурные инварианты (кеш промпта, компакция, гонка рабочего каталога, хуки, делегирование) собраны в [ALTERAN.md](ALTERAN.md) — прочтите раздел Conventions, прежде чем трогать `src/core/`. Там же сказано, какие тесты сторожат каждый инвариант.

## Сообщения об изменениях

Пользовательские изменения попадают в [CHANGELOG.md](CHANGELOG.md) в раздел `Unreleased`. Внутренние правки — нет.

## Релиз

Релиз делает мейнтейнер: поднимает версию в `package.json`, переносит `Unreleased` в раздел с датой и ставит тег `vX.Y.Z`. Тег запускает `publish.yml`, который сверяет тег с версией в `package.json`, повторяет lint, typecheck, тесты и сборку, и публикует в npm.

## Безопасность

Уязвимости не через публичный issue — см. [SECURITY.md](SECURITY.md).
