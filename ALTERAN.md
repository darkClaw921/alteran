# ALTERAN.md

Guidance for agents working in this repository (`alteran` — the terminal coding agent).

## Commands

```bash
pnpm dev -- -p "prompt"        # run the CLI from source (tsx)
pnpm build                     # tsup → dist/cli.js, dist/abr.js
pnpm typecheck                 # tsc --noEmit (TypeScript 7)
pnpm lint                      # biome lint src test scripts (the gate CI enforces)
pnpm format                    # biome format --write; opt-in, see "Conventions"
pnpm test                      # vitest, all suites except the sandbox
pnpm test:sandbox              # agent edge cases in a throwaway container (needs docker)
pnpm test:sandbox:here         # the same suite in the current environment — only inside a container
npx vitest run test/tracker.test.ts -t "ready"   # single suite / single test
node_modules/.bin/tsx scripts/preview.tsx        # static render of the full TUI (no TTY needed)
node_modules/.bin/tsx scripts/drive.ts           # drive the TUI through the fake-TTY harness
node_modules/.bin/tsx scripts/contrast.ts        # audit rendered colours against the background
node_modules/.bin/tsx scripts/pickmodel.ts       # drive /model against the real provider catalog
node_modules/.bin/tsx scripts/bare.ts            # render the console-only layout
node_modules/.bin/tsx scripts/panelcheck.ts      # render the ASTRIA PORTA panel at full width
node_modules/.bin/tsx scripts/promptsize.ts      # token estimate of every system-prompt block
node_modules/.bin/tsx scripts/promptblocks.ts    # print the catalogs exactly as the model sees them
node_modules/.bin/tsx scripts/introcheck.ts      # print frames of the boot animation
node_modules/.bin/tsx scripts/inlinecheck.ts     # prove inline output is written once, never redrawn
node_modules/.bin/tsx scripts/idlecheck.ts       # prove the console writes nothing while idle
```

## Architecture

Single package, ESM, Node ≥ 22.5. Entry points: `src/cli.ts` (commander; TUI, headless `-p`, `tasks`, `mcp`, `doctor`, …) and `src/abr.ts` (tracker CLI alias).

- `src/types.ts` — provider-neutral message model (`ContentBlock`, `Message`, `StreamEvent`, `Usage`). Everything else speaks this shape. A `document` block is carried like an image, but only Anthropic and the Responses API can take one; a plain gateway is told so explicitly rather than handed base64 it would read as text. `Provider.countTokens` is optional on purpose — a gateway without the endpoint must not look like it has one, so callers fall back to the character estimate and say that they did.
- `src/providers/` — `anthropic.ts` (adaptive thinking, prompt caching, eager tool streaming), `openai-responses.ts` (Responses API, reasoning items carried back as `opaque` blocks), `openai-compat.ts` (Chat Completions for OpenRouter / polza.ai / Ollama / LM Studio), `registry.ts` (provider configs, `provider:model` resolution, context windows, pinned gateway routes), `catalog.ts` (model lists with pricing, upstream providers per model, key balance; disk-cached for 6h under `~/.alteran/cache/`).
- `src/core/` — `agent.ts` is the loop: stream → tool_use → hooks → permissions → execute (read-only calls run in parallel, at most `MAX_PARALLEL_TOOLS` at a time and each under its tool's `timeoutMs`) → tool_result → repeat, plus retries with backoff, microcompaction and full compaction; `agents.ts` owns delegation (spawn, continue, cancel, report back); `schedule.ts` owns deferred work (timers, repeats, notifications); `runtime.ts` wires settings, extensions, permissions, hooks, MCP, tracker, session and agents; `commands.ts` implements slash commands; `prompt.ts` builds system prompts; `session.ts` persists transcripts under `~/.alteran/sessions/<project>/`.
- `src/tools/` — Read/Write/Edit/MultiEdit/Glob/Grep/Bash(+background)/WebFetch/WebSearch/TodoWrite/AskUserQuestion/ExitPlanMode/Task/SendMessage/ListAgents/TaskStop/Schedule/ScheduleList/ScheduleCancel/Skill/ToolSearch and MCP resource tools. `web-search.ts` normalizes brave/tavily/searxng behind one tool and refuses to run unconfigured rather than inventing a backend. A tool declares a zod schema, a category (`read|write|bash|network|meta|mcp|tasks`) and `readOnly`; `readOnly` drives both parallel execution and auto-approval.
- `src/tracker/` — the CONSILIUM tracker. `store.ts` owns `.beads/issues.jsonl` (in-memory index + atomic writes under a lock file), `model.ts` mirrors the beads record shape and field order, `cli.ts` is the `br`-compatible command surface, `tools.ts` exposes `tasks_*` to the model.
- `src/permissions/` — Claude-style rule parsing/matching and the decision matrix; `src/hooks/` — Claude-compatible command hooks.
- `src/compat/loader.ts` — discovers agents, commands, skills, plugins, MCP servers, hooks, permission rules and instruction files across Claude Code, Codex, `~/.agents`, Cursor, Gemini and native `.alteran` locations.
- Prompt caching is a prefix match, and the prefix renders as tools -> system -> messages, so the rules are: the MCP tool roster is frozen between turns and sorted by name (`Runtime.syncTools`, applied at a turn boundary in `Agent.send`); the git snapshot in every system prompt is taken once per working directory (`Runtime.envInfo`), so two agents of the same type share a prefix; and any fork of a conversation — compaction above all — must send the same tools, system, route and effort, or it re-reads the whole history at full price. `test/agent.test.ts` -> "prompt cache" asserts that consecutive requests only ever append; it is the standing guard, because a caching regression is otherwise silent.
- Cache breakpoints: the native Anthropic path marks the system block (covering tools + system) and lets the top-level `cache_control` follow the conversation; gateways get the same two through `markCache` in `openai-compat.ts`, where the tail is usually a `tool` message, not a `user` one. `settings.cache.ttl` (default `1h`) suits a terminal session, which pauses while the user reads. `/context` prints the share of prompt tokens served from cache — check it after touching anything that builds a prompt.
- Gateway routing: `settings.routes["provider:model"]` is sent as `provider: { order, allow_fallbacks: false }`, so routing stays inside the chosen list, in the chosen order (the routes pane ticks them with `space`). `/model` (right arrow) and `alteran models --routes` show the prices behind that choice; per-request cost comes back in `usage.cost` and accumulates into the session total.
- `src/tui/` — Ink UI. `store.ts` turns bus events into view state, `render.ts` turns entries into styled lines, `gate.ts` draws the procedural stargate, `stages.ts` classifies activity into the nine GRADUS stages, `components/` holds the panels.

## Conventions

- Everything the UI shows comes from `EventBus` events (`src/core/events.ts`) — add an event rather than reaching into the runtime from components.
- The session's spend gate lives in `Runtime.budgetCheck`, called at the top of `Agent.turns` **before** the model call, so a limit stops the next request instead of billing it first. `warn` reports once and goes quiet; `stop` ends the turn and refuses further ones until `/clear` or `/budget reset`. Session spend is summed from the latest `usage` per agent (`Runtime.sessionUsage`), never from deltas.
- Two kinds of trimming, cheapest first: `Agent.microcompact` rewrites the *content* of old tool results to a one-line note (blocks and `tool_use` ids stay, so nothing is unpaired) once past `microcompact.threshold`; `Agent.compact` pays a model call to summarize only above `autoCompactThreshold`. Once elided, a result is never restored, so anything a turn still needs must be inside `microcompact.keepRecent`.
- A shell may only move the shared working directory if it owns it: `runShell` writes the final `pwd` back only when the call tracks cwd **and** `runtime.cwd` is still the value the call started with, and `ToolContext.direct` (deferred/scheduled runs) turns tracking off entirely. A background or late `cd` must never yank the directory out from under a live turn.
- A write tool's diff has one implementation: `previewWrite` (`src/tools/fs-tools.ts`) applies the edit in memory through the same `applyEdit` the tool uses, and `diffHunks` (`src/tui/render.ts`) renders it once for both the permission prompt and the `/review` overlay. `previewWrite` returns undefined rather than a diff that will never exist, so a prompt never promises a change the tool would refuse.
- Transcript export is a pure renderer (`src/tui/export.ts`): `transcriptMarkdown` maps each entry kind to a markdown shape and `lastAnswers` picks the tail of the answers. `/export` requires a path and resolves it against the working directory; `/copy all` copies the same markdown through `clipboard.ts`, so the two never drift.
- Transcript search is a pure function plus an overlay: `searchEntries`/`entryText` in `src/tui/store.ts` decide what matches (a tool entry is searchable by name, summary *and* result; the splash art matches nothing), and `SearchPanel` previews the match with the transcript's own `entryLines`, so what is previewed is exactly what `enter` scrolls to. Jumping sets `scroll` through `entryOffsets` (`components/Console.tsx`); in the console-only layout the scrollback belongs to the terminal, so `enter` walks the matches instead and the hint says why.
- Attachments are assembled in `Agent.send`, not in the front ends: `/attach` and `/paste` queue paths in `Runtime.pendingImages`, and `@image.png` mentions in the text are lifted by `imageRefs` (`src/core/attachments.ts`). Both end up as `ImageBlock`s ahead of the text block, so headless and TUI behave identically. Only the main agent does this (`isMain`) — an image mentioned inside a delegated prompt is another agent's syntax, not an attachment.
- Every editing tool records into `CheckpointStore` (`src/core/checkpoints.ts`) *after* the write, with both sides of the file in hand; `/undo`, `/redo` and `/checkpoints` drive it from `commands.ts`. It is an ordinary undo stack with a cursor, so a new write truncates the redo side. Two rules matter: a restored file loses its `fileState` mtime, so the next edit must Read it again rather than trust a timestamp from before the rollback; and a file too large to copy is recorded with `skipped` and reported as unrevertable rather than silently missing. Checkpoints are keyed by session (`<id>.checkpoints.jsonl` beside the transcript) and `Runtime.resumeSession` retargets the store, so a continued session can undo what the first one did.
- Hooks are load-bearing in four places: `stop` (`continue: false`) halts the session (`Agent.halted` blocks later turns), `updatedPermissions` adds allow rules, `updatedInput` rewrites a call, and `Notification` is advisory and fired fire-and-forget through `Runtime.notify` (a slow hook must never delay what it describes).
- Delegation goes through `AgentRuns` (`src/core/agents.ts`), never by constructing an `Agent` directly: it owns names, the depth and concurrency budget, the per-agent abort controller and the transcript. A finished agent stays addressable, so nothing may drop it after it reports.
- A scheduled item belongs to the agent that created it (`ScheduledItem.owner`): it fires as that agent, reports back to it, and `ScheduleList`/`ScheduleCancel` are scoped to it — only the orchestrator sees everything. `AgentRuns.stop` drops what a stopped agent deferred, so nothing resurrects it.
- `Runtime.wake` resumes an idle subagent itself through `AgentRuns.resume`; only the orchestrator's turn belongs to the front end (`onWake`). A resumed turn is a background one, so its report bubbles up the tree instead of being dropped.
- Deferred work runs through `Agent.runDirect`, which reuses the loop's hooks, permission checks and `tool_start`/`tool_end` events. Scheduling must never become a way to run something the same command could not run inline.
- A background agent reports through `AgentRuns.drain`, which `Agent.turns` checks before ending a turn, and through `Runtime.wake` when the parent is idle — `Agent.busy` decides which. Both paths are needed: a front end that only implements `onWake` loses reports arriving mid-turn, and vice versa.
- Tracker data must stay readable by `br`: keep the field order in `model.ts`, preserve unknown fields, never write a database file.
- The system prompt only carries what the agent can act on: `Runtime.promptCaps()` decides whether the Task agent catalog, the Skills catalog and the tracker section of `assets/prompts/system.md` are included, and catalog descriptions are summarised (examples stripped, one sentence) rather than pasted whole.
- `src/core/context.ts` estimates what fills the window (system / instructions / catalogs / tool schemas / MCP schemas / conversation) at ~3.5 chars per token; only the total is measured, from the provider's prompt tokens. The VIRES meter, `/context` and the headless report all read the same breakdown, and `CONTEXT_COLORS` in `theme.ts` keeps their colours in sync.
- `Runtime.resumeSession(file)` is the single resume path (CLI `--continue`/`--resume`, `/resume`, the picker): it reassigns `rt.session` to the file being continued, so a resumed session keeps one transcript instead of forking into a new one.
- Transient UI (help `?`, the model picker, permission dialogs) replaces the input area rather than being pushed into the transcript — anything appended there scrolls the conversation and cannot be dismissed.
- Animation is start-up only: `GateState.dialing` (set by the splash alone — never by `GatePanel`) turns on the rim pulse, drifting dust and the chevron dial; the resting panel gate is static and work drives it through `active`/`chevrons`. `app.tsx` repaints idle frames at half the 120ms tick and stops at the first user message; `entryLines` keys the splash by tick so every other entry stays cached.
- The gate is drawn in visual space (a cell counts as 1×2), so `gateSize()` picks a box roughly twice as wide as tall and `renderGate` measures the rim with a gradient-corrected distance; filling a wide panel edge to edge would draw a flattened ellipse. A roundness test guards this.
- The panels are interactive through a focus that lives in `app.tsx`: `tab` cycles console → AGENTS → SCHEDULE, skipping a section with nothing in it, and `x` acts on the highlighted row (`AgentRuns.stop` for an agent, `Scheduler.cancel` for a deferred item). A selection is an index into the rows *drawn*, so the row count comes from the same function the panel renders with — `agentRowCount` (`components/AgentsPanel.tsx`) and `scheduleRowCount` (`components/GatePanel.tsx`) are exported for exactly that reason: computing the room twice would let `x` cancel a neighbour of what is highlighted.
- The left panel's bottom slot shows `SCHEDULE` whenever anything is scheduled and `WORKING TREE` otherwise; the panel layout keeps repainting while an item counts down (`app.tsx` tick), which the console-only layout must never do.
- Palette lives in `src/tui/theme.ts`; every colour must stay ≥3:1 against the panel background (enforced by a test and `scripts/contrast.ts`). Themes: `dark` (default), `contrast`, `design`.
- The console-only layout (the default) renders the transcript through Ink's `<Static>` with the alternate screen off, so finished output becomes ordinary terminal output — the terminal owns scrolling and selection, as in Claude Code. The panel layout keeps the full-screen three-column view on the alternate screen; `ctrl+b` switches, which remounts the app (hence the render loop in `startTui`). `store.settle()`/`store.live()` split entries into "final, already printed" and "still changing"; the splash animates in both layouts until the first user message (nothing is above it to scroll yet) and the console then goes completely still, because any later repaint would drag a scrolled-up terminal back to the bottom, and `store.reset()` bumps a generation that remounts `<Static>`, which otherwise counts what it has already printed and would swallow the first new entry; switching layouts (`ctrl+b`) remounts the app, which is why `startTui` renders in a loop.
- `src/tui/intro.ts` plays the boot animation (dial → kawoosh → travel) on the alternate screen while `Runtime.create` runs, looping the travel frames until it resolves; `settings.intro: false` or `ALTERAN_NO_INTRO=1` skips it.
- Motion is decided in one place (`src/tui/motion.ts`, a pure `motionLevel(settings, env)`): `full` animates the boot and the start screen, `reduced`/`off` draw everything still. It is read before the settings exist — `startIntro` loads them itself, which is why the helper takes a plain settings object rather than a `Runtime`. `NO_MOTION`/`REDUCED_MOTION`/`ALTERAN_MOTION` override the setting, so the convention works without editing a config file.
- The panel layout turns on SGR mouse reporting (`?1000h`/`?1006h`) so the wheel scrolls the transcript one line per notch, and turns it off on exit; `wheelDelta` in `lines.ts` parses the reports and `useInput` swallows them so they never reach the input line. Mouse reporting takes drag-selection away from the terminal, so `F7` / `/mouse` toggles it live (`settings.mouse: false` starts with it off).
- Terminal selection is rectangular across the full screen, so the console-only layout is the default (`bare` state in `app.tsx`, `settings.panels` opts into the side panels, `ctrl+b` toggles) and `ctrl+y` copies the last answer through `src/tui/clipboard.ts` (OSC 52 fallback; `ALTERAN_CLIPBOARD=osc52` skips the helper binaries). `cmd+c` never reaches the process — the terminal copies the selection itself — so `ctrl+c` keeps interrupt/exit.
- Lines are rendered manually (`src/tui/lines.ts`) and Ink only prints them with `wrap="truncate"`; keep wrapping/width logic there, not in components.
- The input line is a pure reducer (`src/tui/editor.ts`): `editKey` decides what a keypress does to `{ text, cursor, mode }` and `PasteBuffer` reassembles a bracketed paste that arrived split across reads. Both are tested without a terminal, which is the point — vi's normal mode and the paste path are exactly the parts that are painful to check by hand. `app.tsx` owns the effects: it swallows the paste on the raw read (in `useInput` every newline would read as Enter and submit early), and hands the draft to `$EDITOR` by leaving the alternate screen — the same trick the layout switch uses.
- Tests run without network: providers are replaced with a scripted stub (`test/scripted.ts`, shared by every suite), the TUI runs on fake TTY streams (`test/harness.ts`).
- `test/sandbox/` holds the agent edge cases that execute real commands and prove that a denied or unapproved one does *not* run. They are excluded from `pnpm test` and refuse to start outside the container (`/.dockerenv` or `ALTERAN_SANDBOX=1`): a regression there should cost a container, not a working tree. The image pins the repo's pnpm version, because a newer one rejects the committed lockfile under its own policy. `test/tracker.test.ts` additionally exercises real `br` interop when the binary is installed.
- Never add `git commit`/`git push` behaviour to agent code paths; the agent must ask the user.
- CI is three workflows, split by what they cost. `ci.yml` runs on every push and pull request (`lint → typecheck → test → build`, matrix Node 22/24, `fail-fast: false`). `sandbox.yml` runs the container suite — nightly, on demand, and on pushes to the main branch — and deliberately *not* on pull requests, so a PR is never blocked by a job that needs to build an image. `publish.yml` runs on a `v*` tag and repeats the same checks before publishing.
- `pnpm lint` is the gate CI enforces; the tree is formatted to Biome's output, so `pnpm format` should be a no-op. When it is not, run it and keep the reformat in the same change as the code it wraps — a separate formatting-only commit buries the real diff and breaks `git blame`.
- Biome is configured for this codebase's idiom rather than its defaults (`biome.json`): `noAssignInExpressions`, `noControlCharactersInRegex`, `noCommaOperator`, `noArrayIndexKey`, `noNonNullAssertion` and `noExplicitAny` are off because the code leans on them on purpose, and `useExhaustiveDependencies` is off for `src/tui/**`, where the render loop manages effect dependencies by hand. Turning one back on is a real change to the code, not a config tweak.
