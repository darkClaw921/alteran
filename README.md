# alteran

Терминальный кодинг-агент (`alteran`) со встроенным трекером задач. Главное отличие от Claude Code / Codex: работа ведётся **фазами** — план превращается в эпики и задачи с зависимостями, которые агент выполняет по одной и закрывает с отчётом. Трекер совместим с [beads](https://github.com/Dicklesworthstone/beads_rust) (`br`): те же `.beads/issues.jsonl`, те же семантики `ready`/`blocked`.

```
alteran                       # терминал (TUI по дизайну Altera)
alteran -p "исправь баги"     # headless-режим
alteran tasks ready           # трекер из консоли (алиас: abr)
```

## Возможности

- **Агент**: цикл модель ↔ инструменты, параллельные read-only вызовы, прерывание по Esc, автокомпакция контекста, сессии с `--continue` / `--resume`.
- **Провайдеры**: Anthropic (adaptive thinking, prompt caching), OpenAI Responses API, любые OpenAI-совместимые — OpenRouter, **polza.ai**, Ollama, LM Studio. Модель задаётся как `provider:model`.
- **Выбор модели (`/model`)**: каталог провайдера с ценами за 1M токенов и размером контекста, поиск по строке, `→` — список апстрим-провайдеров этой модели (цена, контекст, параметры, хранение данных в РФ) с чекбоксами: `space` отмечает нескольких, порядок отметок задаёт приоритет (первый доступный обслуживает запрос), `Tab` — переключение провайдера. Расход за сессию и баланс ключа видны в нижней строке.
- **Трекер CONSILIUM**: эпики-фазы, задачи с acceptance criteria, зависимости (DAG с проверкой циклов), `ready`/`blocked`, комментарии, статистика. Хранилище — `.beads/issues.jsonl`, его же читает `br`.
- **Фазовый workflow**: `/plan` → утверждение → агент `create-tasks` раскладывает план по фазам → `/run-phase 1`, `/run-phase 2` … Агент `run-phase` не начнёт фазу, пока не закрыты предыдущие.
- **Совместимость с экосистемами**: подхватываются агенты, команды, скиллы, хуки, правила доступа и MCP-серверы из Claude Code (`~/.claude`, `.claude/`, плагины из `installed_plugins.json`), Codex (`~/.codex/config.toml`, `skills/`, `prompts/`), `~/.agents/skills`, Cursor и Gemini (`mcp.json`), плюс собственные `~/.alteran` и `.alteran/`.
- **MCP**: stdio / streamable-HTTP / SSE, инструменты `mcp__server__tool`, ресурсы и промпты (как slash-команды). При большом числе инструментов они загружаются лениво через `ToolSearch`.
- **Права (CLIPEUS)**: режимы `default | acceptEdits | plan | autonomous`, правила в синтаксисе Claude (`Bash(git:*)`, `Edit(src/**)`, `WebFetch(domain:x)`, `mcp__server`), безопасные read-only команды разрешаются автоматически, составная команда разрешается только если разрешены все её части.
- **Хуки** Claude-формата: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`, `SubagentStop`, `PreCompact`.

## Установка

```bash
pnpm install
pnpm build
pnpm link --global      # даёт команды `alteran` и `abr`
```

Требуется Node ≥ 22.5 и `ripgrep` (`rg`) для поиска.

## Настройка

`~/.alteran/settings.json` (глобально) и `.alteran/settings.json` / `settings.local.json` (в проекте):

```json
{
  "model": "polza:deepseek/deepseek-v4.1-flash",
  "smallModel": "polza:deepseek/deepseek-v4-flash",
  "reasoning": "high",
  "routes": { "polza:deepseek/deepseek-v4.1-flash": ["morph/fp8", "deepseek"] },
  "providers": {
    "polza": { "type": "openai-compat", "apiKey": "pza_…" }
  },
  "permissions": {
    "defaultMode": "default",
    "allow": ["Bash(pnpm:*)", "Edit(src/**)"],
    "deny": ["Bash(rm -rf:*)"]
  },
  "theme": "dark",
  "panels": false,
  "mouse": true,
  "intro": true,
  "compat": { "claude": true, "codex": true },
  "mcpServers": { "my-server": { "command": "node", "args": ["server.js"] } }
}
```

Ключи берутся из настроек или переменных окружения: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY`, `POLZA_API_KEY`.

`routes` закрепляет апстрим-провайдеров у шлюза (polza/OpenRouter): запрос уходит с `allow_fallbacks: false`, то есть переключение возможно только внутри указанного списка и в указанном порядке. Проще всего задать в `/model` (стрелка вправо, `space`) или командой `/model polza:deepseek/deepseek-v4.1-flash@morph/fp8,deepseek` (`@auto` — снять).

Проверить окружение: `alteran doctor` — провайдеры, модель и маршрут, баланс ключа, трекер, найденные агенты/скиллы/плагины/MCP.

## Сессии

Каждый запуск пишется в `~/.alteran/sessions/<проект>/<id>.jsonl`. Вернуться к работе можно и снаружи, и изнутри агента:

```bash
alteran --continue          # продолжить последнюю сессию проекта
alteran --resume            # выбрать сессию из списка при запуске
alteran --resume 3eae13ed   # по префиксу id
alteran sessions            # список сессий с id, временем и числом сообщений
```

При старте с `--continue`/`--resume` консоль сразу показывает восстановленную переписку и строку `Resumed session … — N messages restored`; если по указанному id сессии нет, агент скажет об этом, а не откроется пустым.

Внутри агента — `/resume`: оверлей со списком (поиск по названию, `↑↓` выбор, `Enter` продолжить), либо сразу `/resume 3eae13ed`. Продолженная сессия становится текущей: новые ходы дописываются в тот же файл, а не создают форк, и переписка восстанавливается в консоли. При выходе агент печатает готовые команды — с id текущей сессии, чтобы скопировать одной строкой:

```
Session 9830989d saved — 12 messages.

  alteran --resume 9830989d   continue this session
  alteran --resume            pick from 6 older sessions
  alteran sessions            list every session of this project
```

## Рабочий цикл фазами

```
> /plan добавить авторизацию в API          # только чтение, агент исследует код
  … план по фазам → диалог утверждения
  [1] Approve and create phased tasks       # запускается агент create-tasks
> /run-phase 1                              # агент run-phase выполняет и закрывает задачи фазы
> /phases                                   # прогресс по фазам
```

Те же данные доступны из консоли и из Claude Code через `br`:

```bash
alteran tasks ready            # что можно брать в работу
alteran tasks show alt-x1.2    # описание, критерии приёмки, зависимости
alteran tasks phase 2          # задачи фазы
br ready                       # beads видит ровно те же задачи
```

## Интерфейс

При запуске, пока грузятся настройки, расширения и MCP-серверы, проигрывается анимация входа: врата набирают девять шевронов, горизонт событий выбрасывает воронку (та самая «kawoosh»), и вид проваливается сквозь тоннель — после чего появляется интерфейс. Если агент ещё не готов, тоннель продолжает лететь, а не замирает на кадре. Анимация идёт на альтернативном экране и не оставляет следов в прокрутке; отключается `"intro": false` или `ALTERAN_NO_INTRO=1`.

Стартовый экран — анимированные врата: по ободу бежит импульс, шевроны набираются один за другим, внутри дрейфует «пыль». Это только заставка: с первой задачей она замирает и допечатывается в терминал как обычный текст, после чего в простое не перерисовывается ничего. Дальше двигается лишь рабочая анимация — горизонт событий во время прогона и шевроны, отмечающие стадии GRADUS.

Три колонки (`ASTRIA PORTA` / консоль / `VIRES`, включаются по `Ctrl+B`): ASCII-врата с девятью шевронами = конвейер GRADUS (ctx → plan → read → patch → typecheck → tests → lint → self-review → commit), git-статус и рабочее дерево слева; метрики контекста, график расхода токенов, задачи фазы, журнал событий и состояние прав справа. При ширине < 158 колонок скрывается левая панель, < 108 — правая.

Шкала `CONTEXT` разбита по цветам и символам на то, из чего складывается окно: системный промпт (`#`), инструкции проекта (`$`), каталог агентов и скиллов (`%`), схемы инструментов (`=`), схемы MCP (`~`), переписка (`+`), свободное место (`-`). Полная расшифровка с токенами и процентами — по команде `/context`.

Тема: по умолчанию `dark` — цвета макета, поднятые до контраста ≥3:1 (в макете декоративные серые почти сливались с фоном терминала). Есть `contrast` (ещё светлее) и `design` (ровно цвета макета). Задаётся в настройках (`"theme": "contrast"`) или переменной `ALTERAN_THEME`.

Вывод CLI (`doctor`, `tasks`, списки) цветной; отключается флагом `--no-color`, переменной `NO_COLOR` или при перенаправлении в пайп.

Нижняя строка: режим, модель, число инструментов, `BUDGET` — занятый контекст, `SES` — токены и деньги за сессию, `KEY` — остаток и лимит ключа провайдера, ветка git. В режиме консоли те же данные — одной компактной строкой под вводом.

По умолчанию (режим консоли) вывод печатается **в обычный буфер терминала**, как у Claude Code: прокрутка колесом, выделение мышкой и `Cmd+C` работают штатно — этим занимается сам терминал. В простое агент не пишет в терминал ничего, поэтому прокрученный вверх экран не дёргается вниз. В режиме с панелями (`Ctrl+B`, либо `"panels": true`) нужен альтернативный экран: там прокрутка идёт колесом через mouse reporting (шаг — одна строка) или `PgUp`/`PgDn`, а выделение перехватывается — его возвращает `F7` (или `/mouse`), состояние видно в подсказках, стартовое задаётся настройкой `"mouse": false`.

`Ctrl+Y` или `/copy` копируют последний ответ целиком, без мыши: через `pbcopy`/`wl-copy`/`xclip`, а при их отсутствии — через OSC 52 (работает и по SSH).

Клавиши: `Enter` — отправить, `\`+`Enter` или `Alt+Enter` — перенос строки, `Esc` — прервать, `Shift+Tab` — режим прав, `Ctrl+O` — развернуть вывод инструментов, `Ctrl+B` — панели, `Ctrl+Y` — копировать ответ, `Ctrl+R` — повторить последнюю стадию, `PgUp`/`PgDn` или колесо — прокрутка (с панелями), `F7` — перехват мыши, `F2` diff, `F3` тесты, `F4` фазы, `F5` перезапуск стадии, `?` — показать/скрыть помощь (оверлей со списком команд, прокрутка стрелками; история при этом не уезжает).

## Команды

`/help`, `/plan`, `/create-tasks`, `/run-phase N`, `/phases`, `/tasks`, `/mode`, `/iris`, `/model`, `/models`, `/context`, `/copy`, `/bare`, `/mouse`, `/reasoning`, `/compact`, `/clear`, `/resume`, `/mcp`, `/skills`, `/agents`, `/plugins`, `/status`, `/init`, `/diff`, `/exit` — плюс все команды и скиллы, найденные в Claude Code, Codex и плагинах.

